The actor workflow

  1. Open Place Actors from Window > Place Actors.
  2. Drag the actor type into the Level Viewport.
  3. Select it in the viewport or Outliner.
  4. Rename it at the top of the Details panel or in the Outliner.
  5. Type exact Location, Rotation, and Scale values in Details.
  6. Move it into the correct Outliner folder.
  7. Save the level with Ctrl + S.

Recover missing panels

  • Outliner: Window > Outliner.
  • Details: Window > Details.
  • Place Actors: Window > Place Actors.
  • Content Drawer: bottom-left button or Ctrl + Space.
  • Default layout: Window > Load Layout > Default Editor Layout.

Viewport movement basics

  • Hold Right Mouse Button and use WASD to fly.
  • Use Q and E while holding Right Mouse Button to move down and up.
  • Mouse wheel changes distance; Right Mouse Button plus wheel changes camera speed.
  • Select an actor and press F to focus the camera on it.

Transform tool basics

  • Q selects without a gizmo.
  • W moves the selected actor.
  • E rotates the selected actor.
  • R scales the selected actor.
  • Space cycles move, rotate, and scale.
  • Use Details for exact values; use the viewport gizmo for rough positioning.

View and test basics

  • Use the viewport's Perspective menu for top/front/side orthographic views.
  • Use Lit, Unlit, and Wireframe to diagnose lighting or blockout shape.
  • Press G for Game View when you want to hide editor icons.
  • Use the Main Toolbar Play button to test inside the editor.

Coordinate choices

  • X runs from the foul line to the pins.
  • Y is the lane width.
  • Z is height.

Gameplay-safe scale

  • Use real lane length for credibility.
  • Use a wider room for camera readability.

Template thinking

  • Props later.
  • Lighting before detail spam.

How to read axes in the viewport

Unreal uses colored transform handles: red is X, green is Y, and blue is Z. For this lane, drag or type red/X values to move down the lane, green/Y values to move left and right, and blue/Z values to change height.

How to enter exact coordinates

Select the actor, open the Details panel, then expand Transform. Type Location, Rotation, and Scale values directly into the numeric fields. Press Enter after each value and save when the object lands correctly.

IN

Mouse-only control design, with the right technical language

The whole game can be controlled with the mouse. The player slides left and right before the throw, holds the left mouse button to enter an aiming/charging gesture, drags upward for power, drags left or right for direction, releases to launch, then lightly steers the ball with mouse movement while it travels down the lane.

Mouse onlyUE5 input lingoFuture ChatGPT ready
Mouse gesture diagramPosition, charge, aim, release, steer

Think of the controls as a small input state machine. Before the throw, mouse X controls the player lane position. While the left button is held, the drag vector controls power and aim yaw. After release, mouse X becomes a light steering input.

PositioningMouse left/right maps to lane-space Y before the throw.
Hold + dragUp sets power. Left/right sets throw direction.
ReleaseBall launches with selected power and yaw.
SteeringAfter launch, mouse X applies a small lateral force.
Pre-throw movementMouseDeltaX -> DesiredLaneY
Move the player/ball spawn left and right across a clamped lane range.
Power gesturePower01 = Clamp(DragUpPixels / MaxPowerDragPixels, 0, 1)
Dragging upward farther gives more launch speed.
Aim directionAimYawDegrees = Clamp(DragRightPixels / MaxAimDragPixels, -MaxYaw, MaxYaw)
Left/right while held creates the slash direction: \ or /.
LaunchForwardVector.RotateYaw(AimYaw) * LaunchSpeed
Release left mouse to apply impulse or set velocity.
Post-release steeringSteerInput = Clamp(MouseDeltaX / SteerSensitivity, -1, 1)
Apply a weak lateral force/torque, much weaker than the launch impulse.

Plain English control loop

  1. Move the mouse left or right to choose where the player stands on the approach.
  2. Press and hold the left mouse button to start the throw gesture.
  3. Drag upward to increase power.
  4. While still holding, drag left or right to angle the throw.
  5. Release the left mouse button to launch the ball.
  6. After release, keep moving the mouse left or right to gently steer the ball.

Technical version

This is a mouse-only lane-space throw mechanic using a pre-launch lateral positioning state, a click-and-drag charge/aim gesture, a launch impulse, and a post-launch steering assist. The important variables are player lane Y, drag vector, normalized power, aim yaw, launch speed, steering input, and steering force.

Input state machineUse these names in Blueprint or C++

These state names are the lingo that will help ChatGPT understand what you want later. Each state has one job, which keeps the control code easier to build and debug.

PositioningNo button held. Mouse X moves the player/ball spawn left and right across the approach.
ChargingLeft mouse button is held. Store DragStartScreenPos and capture the cursor.
AimingUse current drag vector to calculate Power01 and AimYawDegrees.
LaunchOn mouse release, convert power and yaw into a forward launch vector.
SteeringBall is active. Mouse X applies weak lateral force or torque.
ResultWhen the ball reaches pit or stops, score pins and reset for the next throw.

Useful UE5 variable names

CurrentThrowStateEnum: Positioning, Charging, Aiming, Launched, Steering, Result.DesiredLaneYThe player/ball lateral position in lane space.MinLaneY / MaxLaneYClamp limits so the player cannot move outside the allowed approach area.DragStartScreenPosMouse screen position when left button is pressed.CurrentDragVectorCurrent mouse position minus drag start position.Power01Normalized throw power from 0 to 1.AimYawDegreesLaunch angle left/right from the lane centre line.MaxAimYawDegreesMaximum allowed throw angle, for example 12 to 18 degrees.LaunchSpeedMin / LaunchSpeedMaxSpeed range created from power.SteerStrengthHow much control the player has after release.SteerInputMouse X converted to -1 to +1.BallForwardVelocityVelocity down-lane after launch.

Blueprint/C++ event wording

Control event flow
OnMouseMove:
  if State == Positioning:
    DesiredLaneY += MouseDeltaX * PositionSensitivity
    DesiredLaneY = Clamp(DesiredLaneY, MinLaneY, MaxLaneY)

  if State == Steering:
    SteerInput = Clamp(MouseDeltaX / SteerPixelsForFullInput, -1, 1)

OnLeftMouseDown:
  State = Charging
  DragStartScreenPos = CurrentMouseScreenPos
  CaptureMouse()

OnMouseDragWhileHeld:
  CurrentDragVector = CurrentMouseScreenPos - DragStartScreenPos
  Power01 = Clamp(-CurrentDragVector.Y / MaxPowerDragPixels, 0, 1)
  AimYawDegrees = Clamp(CurrentDragVector.X / MaxAimDragPixels, -1, 1) * MaxAimYawDegrees
  State = Aiming

OnLeftMouseUp:
  LaunchDirection = LaneForwardVector rotated by AimYawDegrees
  LaunchSpeed = Lerp(LaunchSpeedMin, LaunchSpeedMax, Power01)
  LaunchBall(LaunchDirection, LaunchSpeed)
  State = Steering

Physics wording

  • Impulse: one strong push at launch.
  • Velocity: directly setting ball movement speed.
  • Lateral force: gentle side push after launch.
  • Torque: spin-based steering, more physical but harder to tune.

Tuning safeguards

  • Clamp lane position to allowed Y range.
  • Add a small deadzone to drag and steering.
  • Limit maximum aim yaw.
  • Make post-release steering subtle.
  • Disable steering after impact or when speed is too low.

Player staging and marker contractWhat the player sees before every throw

The default camera is behind the ball at the foul line, slightly above waist height, looking down the lane. It should feel spooky, but stable enough for accurate aiming.

Player view must show

  • The bowling ball in the foreground.
  • Lane arrows, centre path, gutters, and pin rack.
  • Aim line and power meter while aiming/charging.
  • Score, frame, throw number, and active player or AI name.
  • Zombie pins waiting at the end, with faces readable enough for comedy.
  • Hazards and power-ups without covering the clean ball path.

Subtle player-view motion

  • Gentle camera breathing while idle.
  • Small push-in when the mouse button is held.
  • Very small shake or rumble at maximum power.
  • Light flicker influence from the lane fixtures.
  • No heavy sway during aim. Accuracy beats atmosphere here.

Readable throw flowThe full loop the player should feel

This is the rhythm to test in Play In Editor before adding rare cinematic variants.

1. PromptLane is resolved. UI shows CLICK ANYWHERE TO PLAY. Input for aiming is still disabled.
2. ReturnClick starts a fast blend to TP_Camera_PlayerView. Ball resets to TP_BallSpawn.
3. PositionMouse X moves lane-space Y within MinLaneY and MaxLaneY.
4. ChargeHold mouse. Camera pushes in, power meter rises, ball glow increases, pins react in distance.
5. LaunchRelease. Short shake, aim line disappears, ball trail appears, camera blends to follow.
6. FollowCamera tracks behind and above, looking ahead. If the ball drifts, gutter feedback is clear.
7. ImpactNear the deck, cut or push to show the collision, reaction, and pin scatter.
8. SettleWait for physics to settle. Count pins after they stop, not at first contact.
9. AdvanceStanding zombie pins may twitch and shuffle toward the player, capped by difficulty.
10. RepeatShow result and next prompt. The player clicks to begin the next throw or turn.
Scenario playbooksHow each special moment should work

Each playbook has a trigger, camera action, feedback layer, and exit rule. This keeps comedy moments from dragging or confusing the player.

Last-pin spare drama

Trigger

Camera
Dynamic close-up from final pin transform or Socket_FaceCameraTarget.
Feedback
Brief slow motion, eyes widen, default voice line Uh oh..., impact shake.
Exit
Maximum 1-2 seconds or impact. Then cut to SpareView if the pin falls.

Strike

Trigger
All pins down on first throw after settle.
Camera
Low impact cam, overhead chaos cam, ball POV, pin face cam, or machine reaction cam.
Feedback
STRIKE!, big sound, sparks, machine anger, brief slow motion only for strong hits.
Exit
Return to result/reset after the celebration beat, not after every pin animation finishes.

Open frame

Trigger
Pins remain after the allowed throws.
Camera
Hold on the remaining pins and show them as alive, smug, and dangerous.
Feedback
Laugh, point, wobble, tiny victory dance, score update, OPEN FRAME.
Exit
Advance surviving pins if allowed, then show click prompt.

AI or local turn

Trigger
Turn owner changes.
Camera

Feedback
PLAYER 2 - THROW 2 or ROTTEN RANDY IS LINING UP A SHOT....

Same result/reset/click flow, so the match rhythm stays consistent.

Surviving pin advance rule

Standing pins are not just leftovers. They become the zombie pressure system.

Make the lane spooky without making it unreadable

The lighting target is a readable golden-brown lane surrounded by cold darkness, with dirty green and red accents around the pin deck. The player should always know where to aim.

Lumen readyRect lights

Primary lane recipe

  • Use 4–6 Rect Lights along the ceiling.
  • Keep them mostly cold white or slightly green.
  • Break one or two by lowering intensity or adding flicker.
  • Keep the lane reflection visible.

Back-machine recipe

  • Add a Spot Light behind the pins aimed forward.
  • Use red/green contrast, not pure red everywhere.
  • Let the pins silhouette against fog and machinery.
  • This is your horror focal point.

Intensity: 150–400
Width: 250

Duplicate down-lane

Pin deck light

SpotLight_BackMachine
X=2080, Y=0, Z=180

How to add lights

  1. Open Place Actors > Lights.
  2. Drag Rect Light or Spot Light into the viewport.
  3. Rename it in the Outliner, then move it into 03_LIGHTING.
  4. Type Location, Rotation, Intensity, Source Width, and Source Height in Details.

How to aim the spotlight

Select SpotLight_BackMachine, press E for Rotate, and aim the cone toward the pin rack. For accuracy, type Rotation values in Details after rough aiming in the viewport.

How to judge the pass

Switch the viewport to Lit, press G for Game View, and take a screenshot from the approach. If the ball path or head pin disappears, reduce fog/bloom or raise lane key light.

06

Fog and post process: cinematic, not muddy

Atmosphere sells the abandoned horror feeling, but too much fog kills readability. Use fog as depth and beams, not as a grey blanket over the whole lane.

Exponential Height FogPost Process Volume

Fog starting values

  • Add Exponential Height Fog.
  • Enable Volumetric Fog.
  • Fog Density: 0.015–0.04.
  • Height Falloff: 0.2–0.5.
  • Keep low fog around the pin deck.

Post Process starting values

  • Add a Post Process Volume.
  • Enable Infinite Extent.
  • Use controlled/manual exposure.
  • Vignette: 0.25–0.45.
  • Subtle Bloom and Film Grain.

Where fog settings live

  1. Open Place Actors > Visual Effects.
  2. Drag Exponential Height Fog into the level.
  3. Select it and use Details to enable Volumetric Fog.
  4. Tune Fog Density and Height Falloff in Details while viewing the lane from the gameplay camera.

Where post process settings live

  1. Open Place Actors > Visual Effects.
  2. Drag Post Process Volume into the level.
  3. Select it and enable Infinite Extent in Details so it affects the whole scene.
  4. Set Exposure, Bloom, Vignette, and Film Grain in Details before judging final mood.
Beginner trap: auto exposure can brighten the whole scene and destroy the horror mood. Tame exposure early so your lighting decisions actually stay visible.
Style target: shadows lean blue/green, lane wood stays dirty amber, back-machine danger uses red sparingly, and highlights feel like old fluorescent tubes.
Fog and post-process stackDepth without muddy gameplay

Treat atmosphere as layered visibility control. The highest contrast stays on the playable lane and pin rack; heavier fog belongs at the back machine, floor edges, and distant wall openings.

  • Marker names: code should keep finding the same actor tags and Target Point names.
  • Collision logic: gutter/pit/approach volumes should stay predictable across variants.

Daily editor warm-up

  1. Open the template map.
  2. Open or dock the Content Drawer.
  3. Check Outliner folders are visible.
  4. Select one actor and confirm Details appears.
  5. Press Play once before making big changes.

Common shortcuts

  • Ctrl + S: save current level.
  • Ctrl + Space: Content Drawer.
  • W: move.
  • E: rotate.
  • R: scale.
  • F: focus selected actor.
  • G: Game View.

Panel troubleshooting

  • If Details is blank, select an actor first.
  • If the Content Drawer keeps closing, dock it.
  • If a volume is hard to see, select it in Outliner.
  • If the viewport is slow, lower viewport scalability while editing.
  • If the layout feels broken, reload the default layout.
